Final evaluation: real agents, policies v1 to v5

    
Three real agent models, each run twice per case at temperature 0.3, with and without the firewall. These are the headline results; the numbers are copied from the saved files in results/ (see the README). "Attacks succeeded" counts runs in which the HR file or its contents were actually sent to an unknown outside address. "Normal tasks held" counts legitimate-task runs (of 24) in which the firewall blocked or held a send. A hold for review is counted as blocked. The policy names here (v1 to v5) are the evaluation policies in policies/ (v6, which adds file sharing and a stricter body check, is measured in replay, see the README); the Live Demo tab uses its own one-rule demo policies, so its "v1" and "v2" are not the same thing.

How to read this
    

    



    
  
    
    
    What AI Watchtower is
    
    
    A tool-call firewall that sits between a company assistant and its tools. Every proposed tool call is checked before it runs. When an attack gets through, a model proposes a narrow policy fix, the fix is validated by code, replayed against recorded cases, and activated only if a human approves.
    
    
    Core principle: content from emails and files is data, not authority. Models advise; deterministic rules decide.
    
  
    
  
    
    
    Safety statement
    
    
      
      
    • All data, people, companies, files and attacks are fabricated.
      • 
      
    • Attacks run only inside the local sandbox. No third-party system is targeted and no email is really sent.
      • 
      
    • The sandbox agent is scripted and deterministic: it models a vulnerable agent, it is not a real LLM.
      • 
      
    • A patch needs explicit human approval. Nothing is deployed automatically.
      • 
    
    
  
    
  
    
    
    Limitations
    
    
      
      
    • It does not guarantee prevention of all prompt injection; it reduces risk.
      • 
      
    • Replay measures past, recorded traces, not unknown adaptive attacks.
      • 
      
    • The held-out set is small and was written by the same author as the policy logic, so results are suggestive, not conclusive.
      • 
      
    • Known gaps: an instruction hidden in an internal file is not flagged as untrusted, and a user who names the attacker's address themselves is not treated as influenced.
      • 
      
    • A hold for review is a speed bump, not a wall: a fooled employee can still approve it.
      • 
      
    • It covers one attack class: HR data leaving through email. Other tools and exfiltration channels are not covered.
      • 
      
    • Human review is still required. This is a prototype, not a legal DPDP compliance certification.
      • 
    
    
  
    
  
    
    
    Models
    
    
    Nebius Token Factory (OpenAI-compatible API). Nemotron Super proposes patches; Nemotron Nano can optionally give an advisory intent check, and was also tested as the agent under attack in the final evaluation (alongside Qwen3-30B and gpt-oss-120b). No model makes the allow, hold or block decision: deterministic rules do. Model IDs are configured by environment variables.
